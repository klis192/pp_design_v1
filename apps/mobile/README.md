# Мобильное приложение

Одно приложение «Склад Контур» (`ru.skladkontur.app`) для Android и iOS. После входа роль учетной записи определяет кабинет: собственник/арендатор — телефонный вход, разрешенные помещения/ЛС, финансовые выписки 1С, показания, заявки, документы; исполнитель — вход по паролю, назначенные задания, фото до/после, чек-лист, пауза/отказ, передача результата. Права на API всегда проверяет сервер.

Разрешенные роли задаются при сборке переменной `WAREHOUSE_MOBILE_ROLES` (по умолчанию `tenant,worker`). Учетные записи других ролей отклоняются до загрузки рабочего пространства с предложением войти через веб-версию. Чтобы позже добавить управляющего, достаточно собрать приложение с `WAREHOUSE_MOBILE_ROLES=tenant,worker,manager` и проверить его экраны на телефоне. Административный web CRM сохраняет обычный режим.

Bundle ID `ru.skladkontur.app` после публикации в магазине менять нельзя: другой ID — это другое приложение. Release-ключ Android создается под этот ID один раз и хранится вне репозитория.

Capacitor закреплен на 7.6.9. Web-ресурсы упакованы в приложение; HTTPS origin API задается при сборке, без секретов 1С.

Внутри приложения (`apps/web/src/platform/native.ts`, включается только при наличии нативного моста Capacitor; в браузере поведение прежнее):

- документы, выписки, фото и выгрузки сохраняются во временный кэш и открываются через системное меню «Поделиться» (открыть в просмотрщике, сохранить в «Файлы», отправить в мессенджер) — WebView не поддерживает `<a download>` и blob-ссылки;
- фото (JPEG/PNG/WebP больше 600 КБ) перед отправкой уменьшаются до 2048 px по длинной стороне и пережимаются в JPEG (`apps/web/src/platform/photo.ts`), чтобы укладываться в таймаут запроса на слабой связи; документы и маленькие файлы уходят без изменений;
- просмотр без сети: каждый успешный GET-ответ сохраняется в IndexedDB с привязкой к сессии (`apps/web/src/platform/offline-cache.ts`, до 300 ответов). Если сервер недоступен (нет сети, таймаут, HTML страницы входа Wi-Fi), чтение возвращает сохраненную копию, а над содержимым показывается «Нет связи с сервером… данные, сохранённые …». Действия, которым не нужен ответ сервера для продолжения, без сети ставятся в очередь (см. ниже); остальные показывают ошибку. При возврате связи все данные на экране перезагружаются, при выходе из учетной записи сохраненное удаляется. Файлы (документы, фото) без сети не открываются;
- команды отправляются с `Idempotency-Key`: если ответ сервера потерялся при обрыве связи, повторное нажатие с теми же данными не создаст дубль. Приложение обращается к API с другого origin, поэтому сервер с миграцией `017` и заголовком в CORS нужно развернуть **до** выпуска сборки приложения;
- очередь действий без сети (`apps/web/src/platform/outbox.ts`): комментарий, файл к заявке, фото работы, отметка чек-листа и решения по заданию (начать, приостановить, продолжить, сдать, отказаться) сохраняются в IndexedDB и отправляются по порядку при возврате связи, при запуске и каждые 30 с, с исходным `Idempotency-Key`. Пока очередь не пуста, новые такие действия встают за ней. Отклонённое действие повторяется один раз после успешной отправки следующих (например, «начать» после фото «до»), иначе показывается как «Не отправлено» с причиной. Последовательные решения по одному заданию переносят версию, полученную от собственного предыдущего решения. Показания приборов и создание заявок в очередь не ставятся (нужен ответ сервера); время действия на сервере — время отправки. Выход из учётной записи с неотправленными действиями требует подтверждения и удаляет их;
- токен входа дублируется в `@capacitor/preferences` и восстанавливается при запуске, если iOS очистил хранилище WebView;
- iOS: страница рисуется под вырезом (`viewport-fit=cover`), верхние панели смещаются стилями `styles/mobile-app.css`; в `Info.plist` добавляются описания доступа к камере и фото. Android 15: WebView получает отступы от системных полос (`adjustMarginsForEdgeToEdge: auto`).

```powershell
$env:VITE_WAREHOUSE_API_BASE_URL='https://your-crm.example'
node apps/mobile/scripts/prepare.mjs android
$env:JAVA_HOME='D:/DevTools/temurin21/JDK21-DIRECTORY'
$env:ANDROID_HOME='D:/DevTools/android-sdk'
node apps/mobile/scripts/android-debug.mjs
node apps/mobile/scripts/prepare.mjs ios
npm run test:mobile   # проверка входа собранного www в браузере
```

Генерируемые проекты и web-ресурсы: `.local/mobile/app/`. APK: `.local/mobile/app/android/app/build/outputs/apk/debug/app-debug.apk`. Это тестовая подпись Android, не release-подпись магазина. JDK21/Gradle/SDK устанавливаются отдельно; кэш Gradle по умолчанию находится на диске проекта. API origin должен разрешать доступ с локального origin мобильного контейнера.

Ранее выпускались два отдельных тестовых APK (`ru.skladkontur.client`, `ru.skladkontur.worker`, версия 0.3.0). Это другие приложения: на тестовых телефонах их нужно удалить вручную, обновлением они не заменяются. Каталоги `.local/mobile/client` и `.local/mobile/worker` больше не используются.

Для iOS перенести проект на Mac, установить CocoaPods/Xcode, выполнить `cap sync ios`, выбрать Apple Team и профиль подписи; затем собрать/установить на iPhone. Генерация Xcode-проекта без macOS не создает IPA. Android/iOS-фото используют выбор файла с `capture=environment`; физическая камера, восстановление сессии, фон и потеря сети требуют проверки на устройствах.

## Push-уведомления

Уведомления приложения (новая заявка, комментарий, изменение заявки) приходят на телефон и открывают заявку по нажатию. Push включается отдельно для каждой платформы, только при наличии ключей заказчика; без них приложение к push не обращается (на Android регистрация без Firebase привела бы к падению).

- **Android.** В Firebase-проекте заказчика создать Android-приложение `ru.skladkontur.app`, скачать `google-services.json` и собирать с `WAREHOUSE_GOOGLE_SERVICES_JSON=<путь>`. На сервере задать `FCM_SERVICE_ACCOUNT_FILE` (ключ сервисного аккаунта того же проекта).
- **iOS.** Нужен платный Apple Developer. Включить Push Notifications для Bundle ID, создать APNs-ключ (.p8) и собирать с `WAREHOUSE_IOS_PUSH=1` (скрипт добавит entitlement и обработчики в `AppDelegate`). На сервере задать `APNS_PRIVATE_KEY_FILE`, `APNS_KEY_ID`, `APNS_TEAM_ID`; для сборок из Xcode — `APNS_ENVIRONMENT=sandbox`, для TestFlight/App Store — `production`.
- Сборка без этих переменных убирает ранее добавленные `google-services.json` и entitlement, чтобы iOS-проект подписывался бесплатным Apple ID.

Проверено с поддельными серверами FCM/APNs (`tests/postgres/push.test.mjs`) и имитацией моста Capacitor; доставка на реальные телефоны требует ключей и не проверялась.

**Оставшаяся приемка:** release-подписи Android и iOS, реальные устройства, ключи FCM/APNs заказчика и доставка push на телефоны. Подготовленные проекты/собранный APK не закрывают эти пункты. Для push нужны принадлежащие заказчику проекты Firebase/Apple и ключи доставки; никаких общих демонстрационных ключей в приложение не добавляется.
