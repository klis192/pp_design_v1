# Мобильное приложение · 09.11.2026

Задача: мобильные приложения для исполнителя и арендатора на Android и iOS; публикация в магазинах — позже. Работа в ветке `feat/mobile-single-app` (от `main`, не слита, не развернута). Инструкция по сборке: [apps/mobile/README.md](../apps/mobile/README.md).

## Передача (10.11.2026)

**Состояние.** Ветка `feat/mobile-single-app` отходит от `main` (`c3aff43`), в `main` не слита и не развернута. Одно приложение «Склад Контур» (`ru.skladkontur.app`) для клиента и исполнителя: Capacitor 7.6.9 поверх `apps/web`. Android собран и проверен на эмуляторе Android 15. iOS-проект генерируется, но на iPhone не запускался (нужен Mac).

**Что сделано** (подробно — таблица «Что сделано» ниже):
- одна сборка для двух ролей, вкладки входа «Клиент» и «Сотрудник»;
- скачивание через «Поделиться», вход сохраняется после перезапуска, учтены вырез экрана и системные полосы;
- камера, сжатие фото;
- просмотр без сети;
- очередь действий исполнителя без сети;
- защита от повторов (миграция `017`);
- push через FCM/APNs (миграция `018`), включается только ключами заказчика.

**Как запустить у себя.**
1. `npm ci`, PostgreSQL, `npm run db:migrate`, API на `:3001` (см. корневой README).
2. Для эмулятора — раздел «Проверка на эмуляторе Android» в `apps/mobile/README.md`.
3. Тесты: `npm run typecheck`, `npm test`, `npm run build`, `npm run test:mobile`; PostgreSQL-тесты запускать последовательно (`--test-concurrency=1`).

**Порядок выкладки.** Сначала сервер с миграциями `017`/`018`, потом приложение. Иначе CORS отклонит заголовок `Idempotency-Key`.

**Что осталось:**
- release-ключ Android и `npm run android:release`;
- проверка на реальных Android и iPhone;
- ключи FCM/APNs заказчика;
- ответ заказчика, сколько исполнители бывают без связи;
- на эмуляторе не завершены вход клиента по телефону и отказ управляющему (покрыты `npm run test:mobile`).

**Не попадает в Git:** `.local/` (сборки, Android/iOS-проекты, кэш Gradle), release-ключи, `google-services.json`, ключи FCM/APNs, `.env`.

## Принятые решения

| Решение | Почему | Что отвергнуто |
| --- | --- | --- |
| Capacitor (код интерфейса — `apps/web`) | Мобильные экраны и дизайн уже есть в вебе; один код для веба и приложения; изменения проверяются в браузере. | React Native/Expo — переписывание интерфейса и вторая кодовая база; вернуться к нему стоит, только если исполнители работают без связи часами и нужна отправка в фоне при закрытом приложении. Rust — нет зрелого мобильного UI, iOS-трудности не снимает. |
| Одно приложение `ru.skladkontur.app` для всех мобильных ролей | Одна карточка, подпись, ревью и push вместо двух; Apple отклоняет почти одинаковые приложения одного разработчика (правило 4.3). | Отдельные `ru.skladkontur.client` и `ru.skladkontur.worker`. |
| Роли задаются при сборке (`WAREHOUSE_MOBILE_ROLES`, сейчас `tenant,worker`) | Управляющего можно добавить позже без правок кода. Администратор в приложении не планируется. | — |
| Сначала Android, iOS позже | Android раздается APK без затрат; iOS требует Mac и платный Apple Developer. iOS-проект генерируется тем же скриптом и периодически проверяется. | — |
| Нативное поведение включается только в приложении | Веб-версия для всех ролей работает как раньше; каждое изменение проверено и в браузерной сборке. | — |

## Порядок выкладки

1. Развернуть API и веб из ветки, выполнить `npm run db:migrate` (миграции `017-idempotency-keys.sql`, `018-push-devices.sql`). Новый API без них не запускается.
2. При наличии ключей задать на сервере `FCM_SERVICE_ACCOUNT_FILE` и/или `APNS_*` (см. `.env.example`).
3. Только после этого собирать и раздавать приложение: оно обращается к API с другого origin и использует заголовок `Idempotency-Key`, который старый сервер не разрешает в CORS.
4. Android: `npm run mobile:android`, затем `npm run android:release` с release-ключом; APK раздается напрямую или через RuStore. На тестовых телефонах удалить старые `ru.skladkontur.client`/`ru.skladkontur.worker`.
5. iOS: `npm run mobile:ios`, сборка в Xcode на Mac.

## Что нужно от заказчика

- Release-ключ Android создает и хранит команда (см. README); заказчику — решение, кто владеет ключом.
- Для push на Android: проект Firebase, Android-приложение `ru.skladkontur.app`, файл `google-services.json` и ключ сервисного аккаунта.
- Для iOS: платный Apple Developer (99 $ в год; оплату из РФ нужно решать отдельно), включенный Push Notifications для Bundle ID и APNs-ключ (.p8).
- Ответ, сколько исполнители бывают без связи: минуты (текущего решения достаточно) или часы/смена (тогда приложение исполнителя стоит перевести на Expo ради отправки в фоне).

## Ограничения

- Без сети видно только то, что открывалось со связью; файлы без сети не открываются.
- В очередь не ставятся показания приборов и создание заявок; сервер записывает время отправки, а не время действия; пока связи нет, экран показывает прежнее состояние, а очередь видна в плашке.
- Очередь и push работают, пока приложение открыто или получает push от системы; фоновой отправки при закрытом приложении нет (ограничение WebView).
- Выход из учетной записи без связи не отвязывает телефон от push на сервере.
