# Независимая проверка мобильных ролей

Работа разделена между исполнителями по рабочим сценариям. Отдельно проверены общая оболочка, сохранение функций и допустимость выпуска только интерфейса.

- У исполнителя остаётся один разрешённый основной раздел; пустая нижняя навигация не добавляется. У арендатора доступны три прежних раздела. Права не расширены новыми кнопками.
- В мобильной очереди убраны повторные колонки, но помещение, статус и срок полностью перенесены в основную карточку. Заголовок реестра остаётся доступен клавиатуре и пагинации.
- Список договоров сохраняет срок и приоритет близкого окончания. Подтверждение оплаты использует прежний обработчик; ручная оплата по договору под управлением 1С не разблокируется.
- В чате найдены и исправлены два риска: перенос текста при автоматическом выборе другой заявки после обновления и восстановление уже отправленного черновика после ухода из раздела. Переход ключа обрабатывается до показа/отправки. Успех определяется подтверждением POST, даже если последующее обновление списка не удалось; очищается только исходный черновик.
- В финансовой форме исправлен только нижний предел ввода: 1 → 0,01. Проверены 0,25 и 11 200,25, а также недопустимые ноль, отрицательные и дроби меньше копейки. Восемь GET-выгрузок XLSX сохранили исходную сумму 11 200,25; платежи не создавались.
- Измерение итоговой сборки выявило короткую вкладку шириной 34 px в горизонтальном режиме. Минимальная ширина 44 px исправлена в общем UI-kit; повторные затронутые проверки всех ролей прошли. После этого уточнён только placeholder чата арендатора; три размера проверены отдельно.

Первые ошибки ожиданий тестов сохранены приватно: неуникальное поисковое слово, кадры до загрузки комментариев и ожидание второго элемента как автоматической цели чата. Последнее ожидание исправлено по реальному правилу — сначала открытые, затем по времени обновления. Продуктовое правило ради теста не менялось.

Полные функциональные проверки и два последних изменения представления разделены в [карте проверки](verification.json). Это не прогон аппаратной камеры, доставки сообщений или полной приёмки исходного ТЗ.
